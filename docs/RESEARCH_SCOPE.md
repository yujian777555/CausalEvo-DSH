# CausalEvo-DSH 研究范围与阶段边界

## 科研问题

能否让黑盒 API Agent 根据执行失败生成机制假设，通过受控干预与配对任务重放筛选修改，获得更可靠且可泛化的持续进化？核心研究对象是 Agent 组合的 Prompt、Skill、Tool 或 Workflow；DeepSeek-Flash API 作为固定推理器，不修改服务端权重。

## Phase 0（当前）

平台与缓存测量。仅验证 DeepSeek-Harness 集成、无工具基准、实验重放、Token 计费、环境隔离和真实 API 运行成本。所有结论可被重复计算。

## Phase 1（待规划）

选择可执行且有客观成功判定的任务环境；固定数据集划分、Baseline、评测预算和种子；建立不含进化的强基线。

## Phase 2（待规划）

失败轨迹模式发现与可检验机制假设；建立归因可靠性的定量测试，不仅依赖模型给出的自然语言解释。

## Phase 3（待规划）

针对单一组件的受控干预、配对重放及反事实收益估计；明确不可控环境中的识别局限。

## Phase 4–5（待规划）

带置信/代价约束的进化接受、版本回滚、对照实验、跨任务泛化与消融。谨防仅对训练任务过拟合。

## Phase 6（待规划）

论文写作、图表、可复现附录与科研诚信检查。严禁在未实验时写预设效果。

## 科研与工程边界

缓存命中率高不会自动让因果归因更可靠。缓存优化与算法有效性必须各自设计独立对照。基础模型真实版本可能随远端 API 别名变化，实验日志应记录时间、服务端返回标识（如提供）、参数和重要版本哈希。
